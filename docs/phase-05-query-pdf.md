# PH-A5 Explanation — Query Engine + PDF Report (Phase 5)

**What Phase 5 delivered:** the product's core — `GET /units/{id}/parameters` (dynamic, data-driven selector source), `POST /query` (4 period modes, rows + per-parameter min/max/avg summary, fully access-scoped), `POST /report/pdf` (ReportLab document with the spec's confidential header/footer), and `QUERY_EXECUTED` / `PDF_DOWNLOADED` audits. 12 new tests (45 total passing).

---

## File-by-File

### `backend/app/schemas/query.py` — period as a discriminated union
- Four period models (`DayPeriod`, `MonthPeriod`, `YearPeriod`, `RangePeriod`) share a `mode` literal and are combined via `Field(discriminator="mode")` — Pydantic picks the right model **by the `mode` field**, so `{mode:"MONTH", month:"2026-03"}` validates as one object shape and `{mode:"DAY"}` as another. A malformed month (`2026-13`) or inverted range (`start > end`) is rejected **at validation** (422) — no bad ranges ever reach SQL.
- `QueryRequest{plant_id, unit_id, parameters[], period}` / `QueryResponse{rows, summary}`; row `value` becomes a JSON number (`float`) — clients never see `Decimal`'s JSON string-coding pitfalls.

### `backend/app/services/query.py` — no-ORM-overhead engine
- **`expand_period(period)`**: everything collapses to an inclusive `[start, end]` date pair — DAY passthrough; MONTH via `calendar.monthrange` (handles leap years for Feb); YEAR → Jan 1–Dec 31; RANGE passthrough. One SQL predicate serves all four modes.
- **`run_query(db, unit_id, parameters, period)`**: single indexed SELECT — `WHERE unit_id = ? AND recorded_date BETWEEN ? AND ?` (+ optional `parameter IN (...)`), ordered by date then parameter; this rides exactly on the `ix_plant_data_unit_param_date` index, which is how the <1 s/100k-row requirement is met. The per-parameter **summary is computed in the same pass** (running min/max/sum/count dict) — one scan, no second GROUP BY roundtrip, `n>0` guaranteed per bucket by construction.
- **`unit_parameters(db, unit_id)`**: `SELECT DISTINCT parameter, uom` for the unit, folded in Python so a parameter recorded with uoms `%` and `NULL` yields one row keeping the real uom. This is the **live vocabulary of the plant** — the data-agnostic contract in §4.1 in action.
- `period_label()` renders a display string for audit payloads and PDF headers.

### `backend/app/api/v1/query.py`
- `POST /query` flow: bearer-auth → **`ensure_unit_access`** (403 for unassigned units, the exact message the frontend maps) → unit existence (404) → unit belongs to the declared plant (400 — prevents reading unit names across plants) → run engine → **audit `QUERY_EXECUTED`** (plant/unit/period/parameters/row count) → commit (audit + query share the transaction) → response.
- `GET /units/{unit_id}/parameters`: same access gate, `[{parameter, uom}]`; empty list for units never uploaded to.

### `backend/app/services/pdf.py` — ReportLab (chosen over WeasyPrint for Windows-friendly install)
- Layout built with platypus `SimpleDocTemplate`:
  - **Header**: `GSPC Pipavav Power Corporation Limited — Confidential` (brand-colored title) + sub-lines for plant/unit/period, selected parameters, and `Generated by <user> at <UTC timestamp>` — exactly the spec §1.4 header block;
  - **Body**: repeating-header table (Date | Parameter | Value | UoM) with zebra rows and right-aligned numerics, or a "No data found for the selected criteria." paragraph when empty (an empty result *still produces a valid PDF*, so the UI never has two code paths);
  - **Footer**: `Generated from PS000200 Reporting System` + page number, drawn on every page via the `onFirstPage`/`onLaterPages` callbacks (canvas-level, not flowable — it stamps all N pages).
- Value formatting trims insignificant zeros (`57.2000 → 57.2`).
- Returns `bytes` — the endpoint owns response/audit packaging.

### `backend/app/api/v1/report.py`
- Same body and same access gates as `/query` (identical authorization semantics), then: engines → PDF → **audit `PDF_DOWNLOADED`** including `file_size` (spec payload) → stream with `Content-Disposition: attachment; filename="Unit_1_2026-03-14_2026-03-16.pdf"` (filename is UI nicety; the axios-blob download in Phase 7.3 controls its own name too).

### Notable fixes caught by tests
1. **Date in audit payload → `StatementError: date not JSON serializable`** — JSON columns must hold JSON types; fixed with `model_dump(mode="json")` (JSON-safe dump). This is the pattern for *any* future audit payload that includes dates/UUIDs.
2. My test asserted a 3-row day that the synthetic seed already covers with all 10 parameters — total is 12; corrected the expectation (seed correctness, not engine failure).

## Contract notes for the frontend (Phase 7.3)
- Parameters multi-select options: `GET /units/{unit_id}/parameters` after unit change; `parameters: []` = all.
- PDF: `api.post('/report/pdf', body, {responseType:'blob'})` → object URL download.
- 403 body text: *"You do not have access to this unit"* — surface it verbatim.
